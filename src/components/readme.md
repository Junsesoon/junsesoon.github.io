# components folder readme
수정일: 2026-06-12
- 재사용 가능한 UI 컴포넌트 및 클라이언트/서버 액션 관리 (Cards, Buttons, Tags, Forms 등)

## Files
- `actions.ts`: 클라이언트 컴포넌트에서 폼 제출 시 호출하는 Next.js Server Actions 모음입니다.
  - **게시물 관리**: 핵심 메타데이터인 제목(`title`)을 독립된 컬럼으로 분리 저장하고, 나머지 동적 속성들은 JSONB 스키마(`properties`)를 활용하여 유연하게 게시물을 생성(Create), 수정(Update), 삭제(Delete)하며, 일괄 수정(Batch Update) 기능도 지원합니다. 스킬 트리 게시물의 경우 1:1 확장 테이블(`skilltree`)에 메타데이터를 분리 저장하고, 일반 카테고리로 변경 시 잉여 데이터를 자동으로 정리(Clean-up)합니다.
  - **메타데이터 관리**: 카테고리 템플릿의 생성 및 삭제 등 부가적인 서버 로직을 처리하며, 데이터 변경 후 Next.js 캐시를 즉시 무효화(`revalidatePath`)하여 화면에 최신 상태가 반영되도록 보장합니다. (전역 속성 관리는 `propertyActions.ts`로 분리되었습니다.)
  - **보안**: IP 기반 Rate Limiting을 적용하여 관리자 로그인 시 브루트 포스(무차별 대입) 공격을 방어합니다.
 - `propertyActions.ts`: 전역 속성(Property) 관리를 전담하는 Next.js Server Actions 모음입니다. 전역 속성 및 템플릿 속성의 추가/삭제/이름 변경(Rename 및 **병합**)/필수 여부(is_essential) 토글, **타입(Type) 변경** 등을 처리합니다. 속성을 삭제하거나 이름/타입을 변경할 때 DB 트랜잭션과 안전한 형변환(Safe Casting)을 통해 기존 게시물의 JSONB 데이터(`properties`)를 일괄 동기화하며, **특히 속성 병합(Merge) 시 배열(Array) 및 문자열(String) 데이터를 유실 없이 안전하게 결합하는 고도화된 포맷팅 로직을 지원합니다.** 변환 불가(충돌) 시 원인이 되는 게시물 제목을 역추적하여 데이터 무결성을 철저히 보장합니다.
   - **속성 정규화 (Prop Check)**: 전역 속성 목록과 JSONB 키를 스캔하여 대문자가 포함된 속성을 찾아내고, 원클릭으로 모든 대문자 속성을 소문자로 안전하게 병합(Normalize)하는 기능을 제공합니다.
   - **동기화 및 정리 (Prop Refresh)**: 게시물 데이터(JSONB)에는 존재하지만 전역 목록에 누락된 속성을 찾아 자동 등록(Sync)하고, 어디에서도 사용되지 않는 잉여 속성을 찾아 안전하게 삭제(Garbage Collection)합니다.
   - **온디맨드 조회**: 특정 속성을 삭제하거나 변경할 때, 해당 속성을 사용 중인 게시물 목록만 런타임에 동적으로 빠르게 조회해 오는 기능을 지원합니다.
   - **데이터 정합성 유지**: 메인 `posts` 테이블의 속성명이나 데이터가 변경/병합될 때, 빠른 조회를 위해 분리된 보조 테이블(`skilltree_posts`)의 데이터도 함께 최신 상태로 동기화하는 백그라운드 갱신 작업을 지원합니다.
- `skillTreeActions.ts`: 스킬 트리 관리자 페이지에서 전용으로 사용하는 Next.js Server Actions 모음입니다. 
  - **도메인 관리**: 카테고리(도메인) 목록의 생성/수정/삭제 로직과 드래그 앤 드롭을 통한 노출 순서(`display_order`) 일괄 업데이트 통신을 처리합니다.
  - **스킬 카드 조회**: 스킬 트리 게시물 목록을 불러오는 `getSkillTreeCardsAction`을 담당하며, 메인 `posts` 테이블과 `skilltree_posts` 보조 테이블을 JOIN하여 카드 메타데이터, 속성(`properties`), 본문(`content`)을 한 번에 완벽하게 가져와 빠른 인라인 편집을 지원합니다.
- `publicActions.ts`: 일반 방문자(Public) 전용 Next.js Server Actions 모음입니다.
  - **좋아요 관리**: 게시물의 '좋아요(유익함)' 상태 조회 및 상태 토글 기능을 처리합니다.
  - **보안 (Rate Limit)**: 사용자의 IP와 로컬 스토리지 기반 세션(UUID)을 결합하여, 단시간(10초 이내 5회 초과) 내 무분별한 API 호출 및 도배 공격을 방어합니다.
  - **조회수 관리**: 게시물 상세 페이지 렌더링 시 호출되어 조회수를 집계(`incrementViewCountAction`)합니다. 어뷰징을 방지하기 위해 사용자의 IP를 기준으로 한국 시간(KST) 매일 새벽 4시에 쿨다운이 초기화되도록 처리합니다.
  - **방문자 집계**: 사이트 전역의 순 방문자(Unique Visitor)를 추적(`trackSiteVisitorAction`)합니다. 사용자의 브라우저 세션 ID와 접속 일자를 기준으로 중복을 방지하여 정확한 통계를 기록합니다.
- `EditClient.tsx`: 기존 게시물의 데이터를 불러와 폼에 채워주고, `updatePostAction`을 호출하여 게시물 수정을 처리하는 클라이언트 컴포넌트입니다. URL의 `redirect` 쿼리 파라미터를 읽어 수정 완료 후 이전 페이지(예: 스킬트리)로 매끄럽게 복귀할 수 있도록 분기 처리를 지원합니다.
- `PostEditor.tsx`: 게시물 작성(Create) 및 수정(Edit)을 모두 담당하는 재사용 가능한 폼(Form) UI 컴포넌트입니다.
  - **옵시디언(Obsidian) 스타일 UI**: 폼 테두리와 그림자를 제거하고 속성명 바로 옆에 값을 입력하는 직관적이고 모던한 레이아웃을 적용하여 글쓰기 환경의 사용성과 몰입도를 높였습니다.
  - **동적 폼 구성 및 템플릿 초기화**: 적용할 템플릿을 선택하면 연관된 속성 폼이 자동으로 추가되며, 템플릿 변경 시 이전 템플릿의 잔여 속성들을 깔끔하게 초기화(Reset)하여 에디터 화면을 깨끗하게 유지합니다.
  - **필수 속성 강제**: `PropertyManager`에서 활성화된 전역 필수 속성(`is_essential`)을 불러와 렌더링 시점에 무조건 포함시키며, 프론트엔드 검증을 통해 값이 비어있을 경우 저장을 차단합니다.
  - **이미지 업로드 지원**: 드래그 앤 드롭 및 클립보드 붙여넣기를 통한 Cloudflare R2 이미지 업로드를 처리합니다.
  - **마크다운 삽입**: 업로드 완료 시 올바른 마크다운 문법(`!파일명`)으로 에디터 본문에 이미지를 자동 주입합니다.
  - **불필요한 이미지 정리**: 게시물 저장 시점에 마크다운 본문을 분석하여, 작성 중 에디터에서 지워진 이미지 URL을 찾아내어 R2에서 자동 삭제하도록 API에 요청합니다.
  - **새 속성 타입 지정 및 자동 매핑**: 새로운 속성 추가 시 항상 타입(Type) 선택 드롭다운이 제공되며, 이미 존재하는 전역 속성 이름을 입력할 경우 DB에 저장된 기존 타입을 자동으로 불러와 고정(`disabled`)시켜 타입 충돌을 원천적으로 방지합니다. 또한, 각 데이터 타입(String, Number, Boolean 등)별로 고유한 텍스트 색상을 부여하여 시각적 인지도를 높였습니다.
  - **속성 타입 강제 적용 및 렌더링**: DB에 정의된 속성 타입(String, Number, Boolean, Date, Array)에 맞춰 폼 입력 필드(`<input type="number">`, 체크박스 등)를 동적으로 렌더링하고, 폼 제출 시 안전하게 형변환하여 JSONB 스키마리스 구조 안에서도 입력 데이터의 정합성을 철저히 관리합니다.
  - **옵시디언 스타일 Array(태그) 입력 폼**: Array 타입 속성 입력 시 라운드 배경과 개별 삭제(x) 버튼이 포함된 인라인 태그 컴포넌트(`ArrayTagInput`)를 제공합니다. Enter, Tab 키 입력 또는 커서 이탈(Blur) 시 입력된 텍스트가 새로운 태그로 변환되며, 입력창이 비어있을 때 Backspace를 누르면 마지막 태그를 삭제하는 등 직관적인 데이터 관리 UX를 지원합니다.
  - **스킬 연결 자동완성 (Tag Autocomplete)**: `parentSkill` 및 `childSkill` 입력 시 기존에 등록된 스킬 카드 목록을 조회하여 하단에 뱃지 형태로 나열합니다. `category2`에 입력된 값에 따라 연결 가능한 스킬들이 실시간으로 필터링되며, 뱃지를 클릭하면 기존 문자열 덧붙이기 방식 대신 태그 배열의 새 요소로 즉시 추가되어 편리하고 정확한 스킬 연결 UX를 제공합니다.
- `PostListClient.tsx`: 관리자 대시보드(Admin Dashboard)의 게시물 목록(Data Grid)을 렌더링하고 제어하는 클라이언트 컴포넌트입니다.
  - **목록 제어 및 정렬**: 테이블 헤더를 클릭하여 게시물 목록을 오름차순/내림차순 정렬할 수 있는 기능을 제공합니다.
  - **반응형 UI 및 레이아웃 최적화**: 모바일 및 좁은 창에서 가로 스크롤이 발생하는 이슈를 해결하기 위해 기존의 고정 너비 및 드래그 리사이징 기능을 제거하고, 기기 화면 크기(Breakpoint)에 따라 덜 중요한 열이 자동으로 숨겨지는 반응형 가변 테이블로 전면 개편했습니다. 텍스트 줄바꿈 보정 및 불필요한 좌우 여백(Padding)을 제거하여 화면 공간 효율성을 극대화했습니다.
  - **데이터 표시 확장**: 기존 Like(좋아요) 데이터에 더해 View(조회수) 컬럼을 새롭게 추가하여 목록 내에서 게시물의 트래픽 성과를 직관적으로 확인할 수 있도록 개선했습니다.
  - **일괄 데이터 관리**: 체크박스를 통한 다중 선택 기능과, 선택된 여러 게시물의 Location(Blog, Portfolio, Both) 속성을 모달 창을 통해 한 번에 변경하는 일괄 수정 기능을 처리합니다.
- `LikeButton.tsx`: 게시물 상세 페이지에서 '좋아요(유익함)' 상호작용을 담당하는 인터랙티브 클라이언트 컴포넌트입니다.
  - **Optimistic UI 및 애니메이션**: 서버 응답 대기 없이 즉각적으로 상태를 반영하며, 버튼 클릭 시 파티클 애니메이션을 통해 시각적 피드백을 제공합니다.
  - **상태 동기화 및 쿨다운 방어**: 한 페이지 내에 존재하는 여러 버튼(상/하단) 간의 상태를 커스텀 이벤트(`like-sync`)로 실시간 동기화하고, 무분별한 중복 클릭과 서버 부하 방지를 위해 좋아요를 누른 직후에는 30초간 쿨다운을 적용합니다.
- `ViewTracker.tsx`: 게시물 상세 페이지에 부착되어 화면에 보이지 않게 백그라운드에서 동작하는 클라이언트 트래커 컴포넌트입니다. 페이지 마운트 시 서버 액션(`incrementViewCountAction`)을 호출하여 IP 및 세션 기반(새벽 4시 쿨다운 기준)의 안전한 조회수 집계를 수행합니다.
- `VisitorTracker.tsx`: 애플리케이션 최상위 레이아웃에 부착되어 백그라운드에서 동작하는 전역 방문자 트래커 컴포넌트입니다. 페이지 진입 시 로컬 스토리지의 세션 ID를 확인하고 서버 액션(`trackSiteVisitorAction`)을 호출하여 하루 1회 순 방문자를 집계합니다.
- `TemplateManager.tsx`: 카테고리별로 필요한 프론트매터 속성을 동적으로 관리하는 클라이언트 UI 컴포넌트입니다. 템플릿 및 속성의 추가/삭제 시 서버 액션을 안정적으로 호출하고, 캐시 무효화(`revalidatePath`)를 통해 DB와 화면의 상태를 완벽하게 동기화하여 데이터 정합성을 보장합니다. 기존 전역 속성 추가 시 타입을 자동 매핑 및 고정하며, 데이터 타입별 고유 색상이 적용된 타입 뱃지를 클릭해 즉석에서 타입을 변경하고 연동된 모든 템플릿의 UI를 실시간으로 동기화합니다. **블로그 핵심 기능과 직결된 시스템 예약 속성(title, category 등)은 임의로 조작할 수 없도록 잠금(Locked) 처리하여 안정성을 확보했습니다.**
 - `PropertyManager.tsx`: 전역 프론트매터 속성을 관리하는 클라이언트 UI 컴포넌트입니다. 속성의 추가, 삭제, 이름 수정 및 병합(Merge), 타입 변경, 필수 속성(Essential) 지정 등 모든 CRUD 작업이 서버 액션과 안정적으로 연동됩니다. **시스템 예약 속성의 임의 변경을 방지하는 보호 장치(Locked)가 적용되어 있으며,** 테이블 헤더를 통한 오름차순/내림차순 정렬(Sort) 기능과 데이터 타입별 시각적 색상 구분 기능을 추가하여 관리자 페이지의 UX를 대폭 개선했습니다. 이를 통해 화면에서만 데이터가 변경되는 버그를 해결하고, DB 트랜잭션 및 캐시 무효화를 통해 항상 최신 데이터 상태를 유지하여 신뢰도 높은 관리 경험을 제공합니다.
   - **Prop Check & Refresh**: 대문자 속성 검출/자동 정규화(소문자 변환), 누락 속성 동기화 및 잉여 속성 정리(가비지 컬렉션) 작업을 실행하기 전 추가/삭제/변경될 목록을 미리보기(Preview) 형태로 모달에 띄워 관리자의 안전한 확인 후 실행을 돕습니다.
   - **커스텀 모달 및 사용처 확인**: 속성 삭제(Delete) 시 브라우저 기본 알림창 대신 시각적으로 세련된 커스텀 모달(백드롭 지원)을 띄우며, 온디맨드 방식으로 해당 속성을 사용 중인 게시물 목록을 즉각적으로 조회하여 경고창 하단에 나열해 줍니다.
- `BlogStats.tsx`: 메인 페이지에서 블로그/포트폴리오의 주요 통계(총 게시물 수, 스킬 수, 방문자 수, 좋아요 수)를 시각적으로 보여주는 컴포넌트입니다. 부모 컴포넌트로부터 전달받은 실제 데이터(`totalPosts`, `totalSkills`, `totalVisitors`, `totalLikes`)를 바탕으로 렌더링되며, 내부적으로 `AnimatedNumber`를 활용해 숫자가 0부터 목표 수치까지 부드럽게 증가하는 카운트업(Count-up) 애니메이션 및 카드 호버 입체 효과를 제공합니다.
- `SkillTreeManager.tsx`: 스킬 트리 관리자 페이지(`app/(admin)/admin/skilltree/page.tsx`)의 UI와 상태 제어를 전담하는 클라이언트 컴포넌트입니다.
  - **도메인 및 스킬 카드 CRUD**: 스킬 트리 도메인(그리드)과 스킬 카드 양쪽 모두에 대한 생성/수정/삭제 폼 인터페이스를 통합 제공합니다.
  - **인라인 편집 (Inline Edit)**: 스킬 카드 목록 테이블에서 특정 행(Row)을 클릭하면 폼이 즉시 수정 모드로 전환되어, 에디터 페이지로 이동할 필요 없이 프론트매터 속성들을 즉각적으로 수정 및 저장할 수 있습니다.
  - **드래그 앤 드롭 정렬**: 마우스 및 모바일 터치를 모두 지원하는 네이티브 드래그 앤 드롭 기능으로 도메인 노출 순서를 직관적으로 변경합니다.
  - **반응형 테이블 UX**: 테이블에 `table-fixed` 레이아웃을 적용하고 작은 화면에서 덜 중요한 열(Column)을 자동으로 숨겨 가로 스크롤을 방지했으며, 액션 버튼을 깔끔한 SVG 아이콘으로 교체해 화면 공간 효율성을 극대화했습니다.
- `Footer.tsx`: 모든 페이지 하단에 공통으로 노출되며, 관리자 페이지로 이동할 수 있는 링크를 포함하는 푸터 컴포넌트입니다.
- `SkillTreeGrid.tsx`: DB에서 스킬 트리 게시물을 불러오는 서버 컴포넌트입니다. 동적으로 전달받은 도메인(`matchCategory2`)에 속한 스킬들만 필터링하며, 부모-자식 의존성을 고려한 **Top-Down DFS 기반 배치 알고리즘**을 적용하여 각 스킬 노드의 최적화된 그리드 좌표(Row, Column)를 서버 측에서 미리 계산합니다.
- `SkillTreeInteractive.tsx`: `SkillTreeGrid.tsx`가 계산한 좌표 데이터를 바탕으로 스킬 트리 UI와 **계단형 SVG 연결선**을 렌더링하는 클라이언트 컴포넌트입니다. 마우스/터치 드래그 팬 스크롤 및 정보 팝업 모달 등 상호작용을 처리하며, BFCache 환경에서 뒤로가기 시 드래그 상태가 고착화되는 버그를 완벽히 방지하기 위해 `visibilitychange`와 `pageshow` 이벤트를 모두 활용합니다.
- `GNB.tsx`: 블로그와 포트폴리오 모드 전환 및 관리자 로그인 상태에 따른 토글 버튼을 제공하는 글로벌 내비게이션 바(Global Navigation Bar) 컴포넌트입니다.
- `TOC.tsx`: 게시물의 마크다운 헤딩(`h1~h6`)을 파싱하여 화면 우측에 표시해 주는 반응형 목차(Table of Contents) 컴포넌트입니다.

## Data Boundary
- 컴포넌트는 게시물 콘텐츠 조회를 위해 파일 시스템에 직접 접근해서는 안 됩니다
- 게시물 및 스킬 트리 데이터는 `src/utils/posts.ts`를 통해서만 가져와야 합니다. 이 유틸리티는 DB 스키마를 캡슐화(숨김)하여 기존 UI 컴포넌트가 기대하는 데이터 구조를 그대로 유지해 줍니다
