# components folder readme
수정일: 2026-06-05
- 재사용 가능한 UI 컴포넌트 및 클라이언트/서버 액션 관리 (Cards, Buttons, Tags, Forms 등)

## Files
- `actions.ts`: 클라이언트 컴포넌트에서 폼 제출 시 호출하는 Next.js Server Actions 모음입니다.
  - **게시물 관리**: JSONB 단일 컬럼 스키마(`properties`)를 활용하여 유연하게 게시물을 생성(Create), 수정(Update), 삭제(Delete)하며, 일괄 수정(Batch Update) 기능도 지원합니다. 스킬 트리 게시물의 경우 1:1 확장 테이블(`skilltree`)에 메타데이터를 분리 저장하고, 일반 카테고리로 변경 시 잉여 데이터를 자동으로 정리(Clean-up)합니다.
  - **메타데이터 관리**: 카테고리 템플릿 및 전역 속성을 추가/삭제/이름 변경(Rename)하거나 **전역 필수 여부(is_essential)**를 토글하는 로직을 처리합니다. 특히 속성 이름 변경 시 DB 트랜잭션을 통해 기존 모든 게시물의 JSONB 데이터(`properties`)도 일괄적으로 안전하게 동기화합니다.
  - **보안**: IP 기반 Rate Limiting을 적용하여 관리자 로그인 시 브루트 포스(무차별 대입) 공격을 방어합니다.
- `publicActions.ts`: 일반 방문자(Public) 전용 Next.js Server Actions 모음입니다.
  - **좋아요 관리**: 게시물의 '좋아요(유익함)' 상태 조회 및 상태 토글 기능을 처리합니다.
  - **보안 (Rate Limit)**: 사용자의 IP와 로컬 스토리지 기반 세션(UUID)을 결합하여, 단시간(10초 이내 5회 초과) 내 무분별한 API 호출 및 도배 공격을 방어합니다.
  - **조회수 관리**: 게시물 상세 페이지 렌더링 시 호출되어 조회수를 집계(`incrementViewCountAction`)합니다. 어뷰징을 방지하기 위해 사용자의 IP를 기준으로 한국 시간(KST) 매일 새벽 4시에 쿨다운이 초기화되도록 처리합니다.
  - **방문자 집계**: 사이트 전역의 순 방문자(Unique Visitor)를 추적(`trackSiteVisitorAction`)합니다. 사용자의 브라우저 세션 ID와 접속 일자를 기준으로 중복을 방지하여 정확한 통계를 기록합니다.
- `EditClient.tsx`: 기존 게시물의 데이터를 불러와 폼에 채워주고, `updatePostAction`을 호출하여 게시물 수정을 처리하는 클라이언트 컴포넌트입니다. URL의 `redirect` 쿼리 파라미터를 읽어 수정 완료 후 이전 페이지(예: 스킬트리)로 매끄럽게 복귀할 수 있도록 분기 처리를 지원합니다.
- `PostEditor.tsx`: 게시물 작성(Create) 및 수정(Edit)을 모두 담당하는 재사용 가능한 폼(Form) UI 컴포넌트입니다.
  - **동적 폼 구성**: 글 작성 시 적용할 템플릿을 선택하면 연관된 속성 폼이 자동으로 화면에 추가됩니다.
  - **필수 속성 강제**: `PropertyManager`에서 활성화된 전역 필수 속성(`is_essential`)을 불러와 렌더링 시점에 무조건 포함시키며, 프론트엔드 검증을 통해 값이 비어있을 경우 저장을 차단합니다.
  - **이미지 업로드 지원**: 드래그 앤 드롭 및 클립보드 붙여넣기를 통한 Cloudflare R2 이미지 업로드를 처리합니다.
  - **마크다운 삽입**: 업로드 완료 시 올바른 마크다운 문법(`!파일명`)으로 에디터 본문에 이미지를 자동 주입합니다.
  - **불필요한 이미지 정리**: 게시물 저장 시점에 마크다운 본문을 분석하여, 작성 중 에디터에서 지워진 이미지 URL을 찾아내어 R2에서 자동 삭제하도록 API에 요청합니다.
- `PostListClient.tsx`: 관리자 대시보드(Admin Dashboard)의 게시물 목록(Data Grid)을 렌더링하고 제어하는 클라이언트 컴포넌트입니다.
  - **목록 제어 및 정렬**: 테이블 헤더를 클릭하여 게시물 목록을 오름차순/내림차순 정렬할 수 있는 기능을 제공합니다.
  - **일괄 데이터 관리**: 체크박스를 통한 다중 선택 기능과, 선택된 여러 게시물의 Location(Blog, Portfolio, Both) 속성을 모달 창을 통해 한 번에 변경하는 일괄 수정 기능을 처리합니다.
- `LikeButton.tsx`: 게시물 상세 페이지에서 '좋아요(유익함)' 상호작용을 담당하는 인터랙티브 클라이언트 컴포넌트입니다.
  - **Optimistic UI 및 애니메이션**: 서버 응답 대기 없이 즉각적으로 상태를 반영하며, 버튼 클릭 시 파티클 애니메이션을 통해 시각적 피드백을 제공합니다.
  - **상태 동기화 및 쿨다운 방어**: 한 페이지 내에 존재하는 여러 버튼(상/하단) 간의 상태를 커스텀 이벤트(`like-sync`)로 실시간 동기화하고, 무분별한 중복 클릭과 서버 부하 방지를 위해 좋아요를 누른 직후에는 30초간 쿨다운을 적용합니다.
- `ViewTracker.tsx`: 게시물 상세 페이지에 부착되어 화면에 보이지 않게 백그라운드에서 동작하는 클라이언트 트래커 컴포넌트입니다. 페이지 마운트 시 서버 액션(`incrementViewCountAction`)을 호출하여 IP 및 세션 기반(새벽 4시 쿨다운 기준)의 안전한 조회수 집계를 수행합니다.
- `VisitorTracker.tsx`: 애플리케이션 최상위 레이아웃에 부착되어 백그라운드에서 동작하는 전역 방문자 트래커 컴포넌트입니다. 페이지 진입 시 로컬 스토리지의 세션 ID를 확인하고 서버 액션(`trackSiteVisitorAction`)을 호출하여 하루 1회 순 방문자를 집계합니다.
- `TemplateManager.tsx`: 카테고리별로 필요한 프론트매터 속성(이름, 데이터 타입, 필수 여부 등)을 동적으로 추가 및 삭제하며 관리할 수 있는 클라이언트 UI 컴포넌트입니다.
- `PropertyManager.tsx`: 전역 프론트매터 속성 목록과 사용 횟수를 확인하고, 새로운 속성을 추가하거나 기존 속성을 삭제, **이름 수정(Rename)**, 그리고 **전역 필수 속성(Essential) 지정**을 설정할 수 있는 클라이언트 UI 컴포넌트입니다. 이름 수정 시 연관된 모든 게시물 데이터까지 일괄 업데이트됩니다.
- `BlogStats.tsx`: 메인 페이지에서 블로그/포트폴리오의 주요 통계(총 게시물 수, 스킬 수, 방문자 수, 좋아요 수)를 시각적으로 보여주는 컴포넌트입니다. 부모 컴포넌트로부터 전달받은 실제 데이터(`totalPosts`, `totalSkills`, `totalVisitors`, `totalLikes`)를 바탕으로 렌더링되며, 내부적으로 `AnimatedNumber`를 활용해 숫자가 0부터 목표 수치까지 부드럽게 증가하는 카운트업(Count-up) 애니메이션 및 카드 호버 입체 효과를 제공합니다.
- `Footer.tsx`: 모든 페이지 하단에 공통으로 노출되며, 관리자 페이지로 이동할 수 있는 링크를 포함하는 푸터 컴포넌트입니다.
- `skilltreegrid.tsx`: 마크다운 파일 대신 `getSkillTreePosts()`를 통해 DB에서 스킬 트리 게시물을 불러오는 서버 컴포넌트입니다. 서버 측에서 관리자 인증 토큰을 검증하여 클라이언트 컴포넌트로 관리자 상태(`isAdmin`)를 넘겨줍니다.
- `SkillTreeInteractive.tsx`: `skilltreegrid.tsx`로부터 데이터를 전달받아 스킬 트리 UI를 시각적으로 렌더링하고 사용자 상호작용(드래그, 사이드바 등)을 처리하는 클라이언트 컴포넌트입니다. 사이드바 모달의 Frontmatter 영역을 주요 정보(`startDate`, `endDate`, `summary`)만 보이도록 필터링하고, 관리자 로그인 상태에서는 즉각적으로 게시물 수정을 진입할 수 있는 '수정' 버튼을 제공합니다.
- `GNB.tsx`: 블로그와 포트폴리오 모드 전환 및 관리자 로그인 상태에 따른 토글 버튼을 제공하는 글로벌 내비게이션 바(Global Navigation Bar) 컴포넌트입니다.
- `TOC.tsx`: 게시물의 마크다운 헤딩(`h1~h6`)을 파싱하여 화면 우측에 표시해 주는 반응형 목차(Table of Contents) 컴포넌트입니다.

## Data Boundary
- 컴포넌트는 게시물 콘텐츠 조회를 위해 파일 시스템에 직접 접근해서는 안 됩니다
- 게시물 및 스킬 트리 데이터는 `src/utils/posts.ts`를 통해서만 가져와야 합니다. 이 유틸리티는 DB 스키마를 캡슐화(숨김)하여 기존 UI 컴포넌트가 기대하는 데이터 구조를 그대로 유지해 줍니다
