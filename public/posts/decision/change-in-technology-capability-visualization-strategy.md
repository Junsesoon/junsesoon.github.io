# 배경
- 주니어와 숙련자의 시야 차이로 인한 왜곡을 해소하고자 함
- 각종 비개발 도구를 포함한 시각화 구조가 필요함

# 문제
- **주관적 기준**: [상/중/하] 혹은 [최적화 가능한 수준/작동원리 이해/배우는 중]등 다양한 분류를 고민해봤지만 결국 각자의 이해도에 따라 평가가 주관적으로 갈림
- **정보의 과잉**: 글로 레벨을 표현하면 가독성이 떨어지고 별의 개수로 표현하기에는 객관적인 분류 표현을 그동안 찾지 못함

# 옵션
옵션A: [설계 및 최적화 가능 / 기능 구현 및 운영 가능 / 기술 검토 및 학습 중]로 3단계 분류
- 장점: 어떤 기술을 깊이 있게 팠는지 대략적인 파악 가능
- 단점: 이 기준조차 평가자의 숙련도에 따라 주관적으로 변할 수 있음. 
  *ex) 설계 및 최적화가 가능하다고 했는데 더 좋은 방법을 가지고 있는 사람이 평가한다면 이 사람의 실력은 기능 구현 정도로 내려가야 하는 것 아닌가? 하는 생각이 듦*

옵션B: 기술 친화도 개념 도입
- 장점: 본인이 평가한 친화도이므로 실력과는 무관하게 누가 보더라도 객관적으로 평가할 수 있음
- 단점: 기술의 깊이나 실력이 살짝 가려질 수 있음

# 결정
옵션B: 기술 친화도 개념 도입과 더불어 도메인별 4분할 구조 추가 도입
*도메인별 4분할 구조: Backend / Frontend / Infra / Productivity 로 section을 나눈 후 그 안에서 기술 친화도 순으로 정렬*

# 이유
- 가장 광범위하게 주관적 평가를 커버할 수 있고
- 가려져 있는 기술의 깊이는 오버레이 화면을 통해 숙련도를 보여줄 수 있는 포스팅을 연결하여 보여줄 수 있다고 판단함
